# AXCL HTML 渲染效果测试用例

## 文档目的

本文档用于沉淀 AXCL 文档站点的 HTML 渲染与交互回归测试用例，重点覆盖导航栏、首页入口、语言切换、API 包装页与页面状态保持等场景。

本文档当前以人工回归测试为主，后续如需自动化，可将其中稳定的测试步骤转化为 Playwright 或其他前端自动化脚本。

## 测试范围

当前测试范围包括：

1. 站点根入口默认语言行为。
2. 中文首页和英文首页的导航栏渲染行为。
3. 导航栏的展开、折叠、状态保持与状态隔离。
4. 导航栏的图标、缩进、背景色、hover 色与选中色。
5. 中文 API 包装页与英文 API 详情页之间的导航行为。

## 测试环境

建议至少在以下环境中执行人工回归：

1. 本地构建命令：`make -C docs html`
2. 本地预览目录：`docs/build/html`
3. 浏览器：Chrome 或 Edge 最新版本
4. 语言页面：`/index.html`、`/zh/index.html`、`/en/index.html`

## 执行说明

每条测试用例均包含以下字段：

1. 前置条件
2. 操作步骤
3. 预期结果

执行时应尽量从干净状态开始，必要时清理当前浏览器 tab 的 `sessionStorage`，避免上一次导航状态影响本次验证结果。

## 导航栏测试用例

### TC-NAV-001 根入口默认进入中文

前置条件：

1. 已执行 `make -C docs html`
2. 浏览器可访问站点根页面 `/index.html`

操作步骤：

1. 打开 `/index.html`
2. 观察页面是否自动进入中文页面
3. 检查页面上是否仍保留英文备用入口

预期结果：

1. 根页面默认进入 `/zh/index.html`
2. 页面仍然提供显式英文入口
3. 自动进入中文后不应产生死循环跳转

### TC-NAV-002 中文首页一级目录默认全部展开

前置条件：

1. 浏览器访问 `/zh/index.html`
2. 当前 tab 中没有历史导航状态干扰，或已清理 `sessionStorage`

操作步骤：

1. 打开 `/zh/index.html`
2. 观察第一级目录 `基础`、`开发`、`FAQ`
3. 检查 `基础` 和 `开发` 的展开状态

预期结果：

1. 中文首页默认显示为中文文档导航
2. 第一级可展开目录默认展开
3. 一级目录图标状态与展开状态一致
4. `FAQ` 作为无子项节点，不出现错误的展开子树

### TC-NAV-003 展开与折叠图标风格一致

前置条件：

1. 可访问 `/zh/index.html` 与 `/en/index.html`
2. 导航栏可正常展开和折叠

操作步骤：

1. 分别在中英文页面展开和折叠 `Basic/基础`、`Development/开发`、`C/C++ API`
2. 观察展开与折叠图标的形态、尺寸和对齐

预期结果：

1. 所有可展开目录均使用同一套图标风格
2. 展开与折叠图标尺寸一致
3. 图标在不同层级中保持统一的视觉对齐
4. 当前页、非当前页、hover 态下图标风格不应出现突变

### TC-NAV-004 同级目录展开和折叠互不影响

前置条件：

1. 浏览器访问 `/zh/index.html` 或 `/en/index.html`
2. 页面存在多个同级可展开目录

操作步骤：

1. 展开 `Development/开发`
2. 展开 `Basic/基础`
3. 折叠 `Development/开发`
4. 观察 `Basic/基础` 的展开状态
5. 再次展开 `Development/开发`

预期结果：

1. 折叠 `Development/开发` 不应影响 `Basic/基础`
2. 展开或折叠任一目录时，不应自动修改其他同级目录状态
3. 同级目录之间状态相互独立

### TC-NAV-005 父目录恢复子目录历史状态

前置条件：

1. 浏览器访问包含嵌套目录的页面，例如 `/en/index.html`
2. 导航树中存在 `Development -> C/C++ API`

操作步骤：

1. 展开 `Development`
2. 展开 `C/C++ API`
3. 记录 `C/C++ API` 当前状态为展开
4. 折叠 `Development`
5. 再次展开 `Development`

预期结果：

1. `Development` 折叠后，其子树被整体隐藏
2. 再次展开 `Development` 时，`C/C++ API` 恢复为上次的展开状态
3. 子目录状态不会被父目录折叠动作重置

### TC-NAV-006 主页展开后文本缩进符合层级预期

前置条件：

1. 浏览器访问 `/en/index.html` 或 `/zh/index.html`
2. 已展开 `Development/开发` 与 `C/C++ API`

操作步骤：

1. 观察一级目录文本起点
2. 观察二级目录 `Architecture/架构` 与 `C/C++ API` 文本起点
3. 观察三级目录 `system`、`control` 等文本起点

预期结果：

1. 一级目录文本左对齐一致
2. 二级目录应比一级目录有更深的缩进
3. 三级目录应比二级目录有更深的缩进
4. 不允许出现子项比父项更靠左的情况

### TC-NAV-007 展开与折叠状态下背景色符合预期

前置条件：

1. 可访问导航栏所在页面
2. 可操作展开与折叠交互

操作步骤：

1. 展开 `Development/开发`
2. 展开 `C/C++ API`
3. 折叠 `C/C++ API`
4. 折叠 `Development/开发`
5. 观察各阶段目录背景色变化

预期结果：

1. 展开态背景色符合当前设计预期
2. 折叠态背景色与展开态有明确区分
3. 当前节点、当前路径节点、普通节点背景色层次清晰
4. 多次展开折叠后背景色不应错乱或残留

### TC-NAV-008 hover 与选中状态颜色符合预期

前置条件：

1. 浏览器可访问导航栏页面
2. 存在当前选中页面节点和普通节点

操作步骤：

1. 将鼠标悬停到一级目录节点
2. 将鼠标悬停到二级目录节点
3. 打开当前页面对应节点
4. 比较 hover、当前选中、普通状态的文字色和背景色

预期结果：

1. hover 颜色与当前选中颜色可清晰区分
2. 当前选中节点保持设计指定的文字色和背景色
3. hover 时的图标颜色与文字颜色同步协调
4. 不同层级节点的 hover 和选中色不应相互污染

### TC-NAV-009 中英文导航状态隔离

前置条件：

1. 浏览器可访问中英文页面
2. 同一浏览器 session 中已存在导航状态存储

操作步骤：

1. 在英文页面展开 `Development -> C/C++ API`
2. 切换到中文页面
3. 观察中文页面的导航默认状态
4. 再切回英文页面

预期结果：

1. 英文页面状态只影响英文页面
2. 中文页面状态只影响中文页面
3. 不同语言之间的导航展开状态互不污染

### TC-NAV-010 中文 API 包装页子项点击不跳回英文

前置条件：

1. 浏览器访问 `/zh/dev/c/index.html`
2. 导航栏已展开 `开发 -> C/C++ API`

操作步骤：

1. 点击 `system`
2. 点击 `control`
3. 观察地址栏与页面主体区域

预期结果：

1. 点击导航子项后仍停留在中文 API 包装页上下文中
2. 地址栏应定位到当前中文页内锚点，而不是直接跳转英文详情页
3. 页面正文中可保留英文详情入口作为说明链接

### TC-NAV-011 跨页面导航后目录状态保持

前置条件：

1. 浏览器访问 `/en/dev/c/index.html`
2. 已展开 `Development -> C/C++ API`

操作步骤：

1. 从侧栏点击 `Basic`
2. 观察跳转后导航栏状态
3. 再点击 `Development`

预期结果：

1. 页面跳转后，其他目录的历史展开状态仍被保留
2. 重新展开父目录后，子目录恢复到上次状态
3. 导航状态保持与页面跳转互不冲突

### TC-NAV-016 非首页当前目录文本可折叠当前分支

前置条件：

1. 浏览器访问 `/zh/index.html`
2. 当前 tab 中没有历史导航状态干扰，或已清理 `sessionStorage`
3. 导航栏可访问 `基础 -> 安装指南`

操作步骤：

1. 在中文首页展开 `基础`
2. 点击叶子节点 `安装指南`
3. 进入 `安装指南` 页面后，点击当前父目录文本 `基础`
4. 观察 `基础` 子树是否被折叠

预期结果：

1. 进入非首页叶子页后，当前父目录文本仍可用于折叠当前分支
2. 点击 `基础` 文本后，`基础` 的子项列表被隐藏
3. 折叠动作只影响 `基础` 分支，不影响其他同级目录

### TC-NAV-017 非首页当前目录图标可折叠当前分支

前置条件：

1. 浏览器访问 `/zh/index.html`
2. 当前 tab 中没有历史导航状态干扰，或已清理 `sessionStorage`
3. 导航栏可访问 `开发 -> C/C++ API -> device`

操作步骤：

1. 在中文首页展开 `开发`
2. 展开 `C/C++ API`
3. 点击叶子节点 `device`
4. 进入 `C/C++ API` 中文页后，点击当前父目录 `C/C++ API` 的展开/折叠图标
5. 观察 `C/C++ API` 子树是否被折叠

预期结果：

1. 进入非首页叶子页后，当前父目录图标仍可用于折叠当前分支
2. 点击 `C/C++ API` 图标后，`system/context/control/device/...` 子项列表被隐藏
3. 折叠动作只影响 `C/C++ API` 分支，不影响 `开发` 下的其他同级项

### TC-NAV-018 跨同级叶子导航不应修改兄弟目录展开状态

前置条件：

1. 浏览器访问 `/zh/index.html`
2. 当前 tab 中没有历史导航状态干扰，或已清理 `sessionStorage`
3. 导航栏可访问 `开发 -> C/C++ API -> device` 与 `开发 -> Python API`

操作步骤：

1. 在中文首页展开 `开发`
2. 展开 `C/C++ API`
3. 点击叶子节点 `device`
4. 在 `device` 所在页面中点击 `Python API`
5. 观察跳转后的导航栏中 `开发` 与 `C/C++ API` 的展开状态

预期结果：

1. 从 `device` 跳转到 `Python API` 后，`开发` 目录保持展开
2. `C/C++ API` 的历史展开状态保持不变，不应因点击 `Python API` 被折叠
3. `Python API` 作为 `开发` 下的同级叶子，不应影响 `C/C++ API` 的展开/折叠状态


### TC-NAV-019 hover 不应向父目录冒泡高亮

前置条件：

1. 浏览器访问 `/zh/index.html` 或 `/en/index.html`
2. 导航栏中存在至少两级目录，例如 `开发 -> C/C++ API -> device`

操作步骤：

1. 将鼠标悬停到叶子节点 `device`
2. 观察 `device` 的父目录 `C/C++ API`
3. 将鼠标悬停到目录项 `C/C++ API`
4. 观察 `C/C++ API` 的父目录 `开发`

预期结果：

1. 悬停 `device` 时，仅 `device` 自身高亮，`C/C++ API` 不应被高亮
2. 悬停 `C/C++ API` 时，仅 `C/C++ API` 自身高亮，`开发` 不应被高亮
3. hover 只作用于当前鼠标所在节点，不向父目录冒泡高亮

### TC-NAV-020 叶节点切页刷新应平滑

前置条件：

1. 浏览器访问 `/zh/index.html`
2. 导航栏中存在 `开发 -> C/C++ API -> device` 与 `开发 -> Python API`

操作步骤：

1. 展开 `开发`
2. 展开 `C/C++ API`
3. 点击叶节点 `device`
4. 在 `device` 页面点击叶节点 `Python API`
5. 观察页面切换过程中的内容和侧栏表现

预期结果：

1. 从 `device` 跳转到 `Python API` 时，页面切换不应出现明显跳闪
2. 侧栏与正文应以平滑过渡方式完成刷新
3. 新页面加载后，当前目录状态仍应保持正确

### TC-NAV-012 主页点击目录文本递归折叠正确

前置条件：

1. 浏览器访问 `/zh/index.html`
2. 当前 tab 的 `sessionStorage` 已清理，避免历史导航状态干扰
3. 页面初始可见 `开发` 节点，且可通过文本点击切换折叠状态

操作步骤：

1. 点击一级目录文本 `开发`，确认一级目录折叠
2. 再次点击一级目录文本 `开发`，恢复一级目录展开
3. 点击二级目录文本 `C/C++ API`，展开子目录
4. 再次点击二级目录文本 `C/C++ API`，折叠子目录
5. 再次点击二级目录文本 `C/C++ API`，恢复子目录展开
6. 点击一级目录文本 `开发`，折叠父目录
7. 再次点击一级目录文本 `开发`，恢复父目录展开
8. 检查 `C/C++ API` 是否保持上次展开状态
9. 按子目录到父目录的顺序，先点击 `C/C++ API` 文本折叠子目录，再点击 `开发` 文本折叠父目录

预期结果：

1. 在主页点击目录文本时，不应跳转到其他页面，而应切换对应目录的展开和折叠状态
2. 按父目录到子目录顺序操作时，各级目录折叠和展开行为正确
3. 按子目录到父目录逆向操作时，各级目录折叠和展开行为正确
4. 父目录重新展开后，子目录应保持父目录折叠前的上次状态

### TC-NAV-014 点击非子目录文本后按文本逆向折叠仍然正确

前置条件：

1. 浏览器从 `/zh/index.html` 进入
2. 当前 tab 的 `sessionStorage` 已清理，避免历史导航状态干扰
3. 页面中存在至少两级可展开目录，例如 `开发 -> C/C++ API`
4. 本用例必须覆盖当前中文导航中的全部非子目录叶子项，而不是只抽样验证单个示例

操作步骤：

1. 对 `基础` 下全部叶子项依次执行验证：`概览`、`安装指南`、`快速开始`
2. 每进入一个 `基础` 叶子页后，点击 `基础` 目录文本，确认一级目录可折叠
3. 对 `开发 -> C/C++ API` 下全部叶子项依次执行验证：`system`、`context`、`control`、`device`、`engine`、`event`、`memory`、`mock`、`stream`
4. 每进入一个 `C/C++ API` 叶子页或锚点后，先点击 `C/C++ API` 目录文本，检查子目录折叠
5. 再点击 `开发` 目录文本，检查父目录折叠
6. 如需验证正向展开链，可从主页先点击目录文本依次展开 `开发` 和 `C/C++ API`，再进入对应叶子项

预期结果：

1. 点击每个非子目录导航文本后，应进入对应页面或页面锚点
2. 进入任一目标页面后，当前激活路径上的目录文本仍可触发折叠，而不是被错误强制导航
3. 对全部 `基础` 叶子项，点击 `基础` 文本后均应可折叠一级目录
4. 对全部 `C/C++ API` 叶子项，点击 `C/C++ API` 文本后均应可折叠子目录，再点击 `开发` 文本后均应可折叠父目录
5. 不允许出现仅部分叶子项可折叠、而其他叶子项失效的情况
